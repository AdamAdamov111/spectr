# SPECTR · Платформа доверенных данных и цифровых двойников

MVP-стенд по инженерному блюпринту SPECTR (версия 1.0, 14 сентября 2026): семантический слой с правом записи над SAP/1С/АСУ ТП/СЭД для нефтегазовых госкомпаний — онтология как код, explain до строки источника, маркировки безопасности в данных, действия с write-back и криптографический аудит.

## Что здесь

| Каталог | Содержимое | Статус |
|---|---|---|
| `ui/` | Рабочее место SPECTR: 14 экранов U1–U14 + видеостена `/wall` (React 19, TypeScript, Vite) | **готово, работает без бэкенда** |
| `ui/src/data/` | Браузерный стенд: генератор синтетического холдинга «Северная нефть», Object API (поиск, обход, explain, функции, действия), PDP/PEP с маскированием, аудит с хеш-цепочкой и Merkle-proof (WebCrypto) | готово |

## Запуск UI-стенда

```bash
cd ui && npm install && npm run dev
```

Откройте http://localhost:5173. Операторы: `sc_head` (руководитель СЦ), `toir_eng` (инженер ТОиР), `seb_analyst` (СЭБ, допуск FIN+PII под целью `procurement_check`), `analyst_open` (без допусков). Пароль для всех: **NickThe001**.

Статическая сборка для публикации: `SPECTR_BASE=/spectr/ npm run build` → `ui/dist`.

## Сквозной сценарий (часть 2.3)

1. Ситуационный центр: карта активов, красная НПС-2 (аномалия давления 0.87). Клик → карточка, свойство `pressure_anomaly_score` → Explain: датчик P-104, окно 15 мин, пайплайн `anomaly_v3`, коммит, сырой файл телеметрии, строка 88 412.
2. Связь «имеет оборудование» → `Насос-104`: golden-объект из SAP PM + 1С:ТОиР + паспорта (crosswalk), индекс состояния 0.41, три открытые заявки из 1С, акт из СЭД с упоминанием подрядчика.
3. `ООО «Вектор»`: собран из SAP, 1С, ЕГРЮЛ и трёх писем; учредитель Иванов И.И. — также учредитель `ООО «Стрела»`, обе в тех же 6 закупках, `cartel_pattern` 0.72 с explain факторов.
4. Действие «Поставить контрагента на контроль» (роль СЭБ): предпросмотр diff, предусловия, Temporal-воркфлоу `ЗАПИСЬ → ПЕРЕДАЧА В CRM → ПОДТВЕРЖДЕНИЕ`, статус `pending_writeback`, chaos-тест отказа источника с компенсацией.
5. ИИ-помощник: «Какие подрядчики НПС-2 связаны с ООО Вектор и сорвали сроки за квартал?» — ответ с проверенными ссылками на объекты и трассой инструментов; без допуска FIN суммы скрыты.
6. Инспектор аудита: кто смотрел `ООО «Вектор»`, с какой целью, inclusion proof в Merkle-корне (проверка в браузере, имитация подмены даёт «НАРУШЕНИЕ»).
7. Ветки данных: `dev/backfill-2026-08`, перезапуск пайплайна ТОиР, diff по датасетам, merge с проверками.

## Инварианты, которые стенд показывает буквально

- Маскирование выполняется до отрисовки: значение с маркировкой вне допуска приходит как `masked: true` с причиной (спец. 9.2), фильтр по `_mk` применяется до подсчёта результатов поиска.
- Маркировка связи = ⊔ маркировок обоих концов: скрытые политикой узлы графа показаны контуром с замком.
- Действия только через предпросмотр, предусловия и подтверждение; агент лишь предлагает действие.
- Аудит: подпись, `prev_hash` → `hash`, Merkle-корень каждые 16 событий, якорь WORM, inclusion proof O(log n).

## Дизайн-система

Токены в `ui/src/design/tokens.css` (цвет, движение 8.7, плотность), оболочка в `app.css`, экраны в `screens/screens.css`. Ориентиры: palantir/blueprint (плотные data-интерфейсы), shadcn/ui + Radix (анатомия компонентов, cmdk-палитра), Magic UI и Aceternity UI (border beam, shine, spotlight, dot pattern, number ticker), Tremor (KPI-карточки со спарклайнами). Все эффекты реализованы собственным CSS/Canvas без внешних зависимостей, чтобы стенд работал в изолированном контуре.

## Ограничения стенда

Карта — схематическая проекция на canvas (в проде MapLibre + deck.gl с офлайн-тайлами); граф — собственный canvas-рендер (в проде Sigma.js + ForceAtlas2 в Worker); LLM-помощник — детерминированные инструменты над онтологией без модели (в проде Qwen через vLLM внутри контура). Все данные синтетические и помечены `SYNTHETIC`.
